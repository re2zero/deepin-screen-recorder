依据：`at-case-authoring` 技能规范（标题【模块】功能_场景、前置只写状态、步骤一行一动作、期望为**整个用例执行完后的最终期望结果**、断言词不进步骤、不可自动化标【人工】）

## 说明

- 每个待补 suite case 覆盖多条原始用例（变体合并），case 内步骤串联各场景。
- 步骤严格一行一动作，动词 + UI 目标 + 参数。
- **期望（expected）= 前置 + 全部步骤执行完后的最终期望结果**，每条是可断言的最终状态；不是每个步骤对应一个期望。
- 涉及视觉/颜色/悬停/性能等不可自动化断言 → 标 `manual: true` + 标题前缀【人工】。
- 前置条件只写状态，可断言；构造不了标 `[手工]`。
- 运行时定位依赖的元素见文末「实施前置：元素命名缺口」，需开发补 AccessibleName 后方可生成可运行 suite。
